# Wazuh manager and maintained detection mappings

This topology runs Wazuh Manager without indexer or Wazuh Dashboard. Native rules remain enabled. The mounted `rules/ahr_falco_rules.xml` adds 31 AHR rules: 3 generic Falco mappings, 16 specific runtime mappings, 9 HTTP classification rules and 3 repeat-event correlations. The standard sample `etc/rules/local_rules.xml` is separate.

At every startup, `entrypoint-scripts/10-manager-only.sh` synchronizes the maintained AHR file into the persistent `wazuh_etc` volume. Edit the host source, not only the container copy. A missing source file fails startup instead of silently retaining old rules.

```powershell
docker restart --timeout 30 ahr-idps-wazuh-manager-1
docker exec ahr-idps-wazuh-manager-1 /var/ossec/bin/wazuh-analysisd -t
docker exec ahr-idps-wazuh-manager-1 /var/ossec/bin/wazuh-control status
```

The manager reads Suricata EVE and Falco JSON through shared volumes. Repeat-event rules group by src_ip and dest_ip with frequency 5 over 60 seconds. A proxy-leg IP is not necessarily the original client; correlate with Nginx before attributing an incident or requesting a response.

Agent ports 1514/1515 and the optional API 55000 bind to loopback. Enable the API overlay using `scripts/start_wazuh_api.sh`; HTTPS 55000 is an authenticated API, not a web dashboard. Registration secrets are generated by `scripts/wazuh_prepare.sh` and must not be committed.
